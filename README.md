# آشیان

پلتفرم آگهی اجاره و فروش ملک در دبی، برای فارسی‌زبانان. راست‌چین، سریع و ساخته‌شده برای ۳۰ هزار کاربر هم‌زمان.

نقشه‌ی راه مرحله‌به‌مرحله در `roadmao.md` و قواعد پروژه در `CLAUDE.md` است.

## پیش‌نیازها

- Node.js نسخه‌ی ۲۲٫۱۲ یا بالاتر
- pnpm (`npm install -g pnpm`)
- Docker فقط برای حالت `full` لازم است

## راه‌اندازی سریع (بدون Docker)

```bash
pnpm install
copy .env.example .env      # در macOS/Linux: cp .env.example .env
pnpm dev
```

با یک دستور همه‌چیز بالا می‌آید:

| سرویس                 | آدرس                                |
| --------------------- | ----------------------------------- |
| سایت                  | http://localhost:3000               |
| API                   | http://localhost:4000               |
| مستندات API (Swagger) | http://localhost:4000/docs          |
| سلامت سرویس‌ها        | http://localhost:4000/health/ready  |
| دیتابیس (PGlite)      | postgres://127.0.0.1:54329/postgres |

## دو حالت اجرا

متغیر `INFRA_MODE` در `.env` تعیین می‌کند هر سرویس زیرساختی چگونه تأمین شود.
کد برنامه در هر دو حالت یکسان است و فقط آداپتورها عوض می‌شوند.

| سرویس   | `lite` (توسعه، بدون Docker)  | `full` (نزدیک به production)     |
| ------- | ---------------------------- | -------------------------------- |
| دیتابیس | PGlite + PostGIS (فایل محلی) | PostgreSQL + PostGIS + PgBouncer |
| صف      | BullMQ روی PostgreSQL        | BullMQ روی Redis                 |
| کش      | داخل حافظه                   | Redis                            |
| فایل    | پوشه‌ی `.data/uploads`       | MinIO / S3                       |
| جستجو   | موتور داخل حافظه (داخل API)  | Typesense                        |

برای حالت full:

```bash
pnpm infra:up               # بالا آوردن Postgres، Redis، Typesense، MinIO
# در .env: INFRA_MODE=full و DATABASE_URL را روی PgBouncer بگذارید
pnpm dev
```

> حالت `lite` فقط برای توسعه است. اهداف کارایی (۳۰ هزار کاربر هم‌زمان) برای حالت `full` تعریف شده‌اند.

## دیتابیس و داده‌ی نمونه

`pnpm dev` خودش جدول‌ها را می‌سازد و روی دیتابیس خالی **۵٬۰۰۰ آگهی واقع‌نما در ۳۰ محله‌ی دبی**
(با ۴۰ مشاور و حدود ۲۹ هزار عکس جای‌نگهدار) می‌ریزد؛ بار اول حدود ۱۵ ثانیه.

```bash
pnpm --filter @ashian/db generate        # ساخت migration جدید بعد از تغییر schema
pnpm --filter @ashian/db migrate         # اعمال migrationها
pnpm --filter @ashian/db seed            # فقط روی دیتابیس خالی
pnpm --filter @ashian/db seed -- --force # پاک‌سازی و ساخت دوباره
```

## API

مستندات تعاملی: http://localhost:4000/docs

| مسیر                                              | توضیح                                            |
| ------------------------------------------------- | ------------------------------------------------ |
| `POST /v1/auth/otp/request` و `/verify`           | ورود با موبایل و کد یکبارمصرف (کوکی httpOnly)    |
| `POST /v1/auth/refresh` و `/logout`, `GET /me`    | نشست                                             |
| `GET /v1/locations` , `/tree`, `/:slug`           | محله‌ها و برج‌ها با تعداد آگهی                   |
| `GET /v1/agents` , `/:id`                         | مشاوران (مشاور برتر اول)                         |
| `GET /v1/listings/:publicId`                      | جزئیات آگهی                                      |
| `POST/PATCH/DELETE /v1/listings`, `/:id/submit`   | ساخت، ویرایش، حذف، ارسال برای بررسی              |
| `POST /v1/media/presign`، `/:id/complete`         | آپلود مستقیم عکس و پردازش در worker              |
| `GET/PUT/DELETE /v1/favorites`                    | علاقه‌مندی‌ها                                    |
| `GET /v1/search/listings`                         | جستجو، فیلتر، facet و چینش منصفانه               |
| `GET /v1/search/map`                              | پین و خوشه‌ی آگهی‌ها در محدوده‌ی نقشه            |
| `GET /v1/search/suggest`                          | پیشنهاد خودکار: محله، برج، مشاور، آژانس، کد آگهی |
| `GET /v1/system/search`، `POST …/reindex` (ادمین) | وضعیت ایندکس و ساخت دوباره                       |

**ورود در توسعه:** کد پیامک در لاگ API چاپ می‌شود و در پاسخ `otp/request` هم به‌صورت `devCode` می‌آید
(فقط وقتی `NODE_ENV` غیر production و `SMS_PROVIDER=console` باشد). کاربر ادمین نمونه: `971500000000`.

## جستجو

جستجو و فیلتر **فقط** از موتور جستجو سرو می‌شود (Typesense در حالت full)؛ PostgreSQL فقط منبع اصلی داده است و
در درخواست کاربر هیچ‌وقت خوانده نمی‌شود. کارت آگهی (قیمت، عکس، مشاور …) داخل خود سند ایندکس است.

**پارامترهای `GET /v1/search/listings`** (همه در URL می‌مانند؛ ارقام فارسی و عربی هم پذیرفته می‌شوند):
`q` (متن یا کد آگهی)، `dealType`، `propertyType`، `location` (مسیر مثل `dubai/dubai-marina`، شامل زیرمجموعه‌ها)،
`priceMin/Max`، `bedroomsMin/Max`، `bathroomsMin`، `areaMin/Max` (فوت مربع)، `furnishing`، `amenities` (همه‌ی موارد)،
`verified`، `cheques`، `parkingMin`، `postedWithin` (روز)، `agentId`، `bbox` (`west,south,east,north`)،
`sort` (`relevance` `newest` `price_asc` `price_desc` `area_desc`)، `verifiedFirst=1` («تأییدشده‌ها اول»)،
`page`، `pageSize`، `facets=0` (بدون شمارش).

- **facet ناهم‌پیوند:** تعداد کنار هر گزینه فیلتر خود همان گروه را نادیده می‌گیرد؛ با انتخاب «ویلا» تعداد «آپارتمان» صفر نمی‌شود.
- **چینش منصفانه:** حداکثر ۳ آگهی ویژه در هر صفحه، در جایگاه‌های ثابت ۱، ۵ و ۹ (`placement: "featured"` برای برچسب «ویژه»)؛
  ویژه‌ها بین صفحه‌ها می‌چرخند و تکرار نمی‌شوند؛ هیچ مشاوری بیش از ۲ آگهی پشت‌سرهم ندارد (مرز صفحه‌ها هم)؛
  آگهی قدیمی یا بی‌کیفیت (کمتر از ۳ عکس، امتیاز کیفیت پایین) در «مرتبط‌ترین» امتیاز کمتری می‌گیرد.
  چینش تا ۲۵۰ نتیجه‌ی اول انجام می‌شود؛ صفحه‌های دورتر ترتیب موتور را بدون ویژه نشان می‌دهند.
- **غلط تایپی و فارسی:** متن قبل از ایندکس و جستجو یکسان می‌شود (ی/ک، ارقام، نیم‌فاصله، اعراب)؛ تا ۲ غلط تایپی و پیشوند پذیرفته است.
- **نقشه:** خوشه‌بندی با geohash (دقت بر اساس زوم)؛ محدوده‌ی کم‌آگهی یا زوم نزدیک، همه‌ی پین‌ها تکی.

**همگام‌سازی:** هر تغییر آگهی فعال (ویرایش، حذف، عکس اصلی) یک job `search.sync-listing` می‌سازد که وضعیت فعلی را از
دیتابیس می‌خواند و سند را به‌روز یا حذف می‌کند. هر کدی که وضعیت آگهی را عوض می‌کند (مثلاً تأیید ادمین در مرحله ۱۲)
باید `ListingsService.requestSearchSync()` را صدا بزند.

```bash
pnpm search:reindex   # ساخت دوباره‌ی کامل (ایندکس تازه + جابه‌جایی اتمیک alias؛ جستجو قطع نمی‌شود)
```

در حالت full بعد از اولین `pnpm infra:up` ایندکس خالی است و API هنگام شروع خودش reindex صف می‌کند (worker باید بالا باشد).
پیشنهاد: `pnpm search:reindex` را شبانه با cron اجرا کنید تا امتیاز تازگی تازه شود.
در حالت lite ایندکس درون‌حافظه‌ی پروسه‌ی API است (worker به آن دسترسی ندارد)، پس API خودش هنگام شروع آن را از دیتابیس
می‌سازد (حدود ۲ ثانیه برای ۵ هزار آگهی) و صف `search` را مصرف می‌کند؛ تأخیر sync در lite تا ۵ ثانیه است.

**تست بار:** `pnpm --filter @ashian/api search:load -- --concurrency=500` (بدون ابزار خارجی) یا
`k6 run apps/api/load/search.k6.js` (آستانه‌ها: p95 زیر ۳۰۰ms و پیشنهاد زیر ۵۰ms). برای اجرا روی یک IP،
`RATE_LIMIT_MAX` را موقتاً بالا ببرید.

## صفحه‌ی اصلی

صفحه‌ی `/` استاتیک است (ISR، هر ۵ دقیقه) و همه‌ی داده‌اش از یک درخواست کش‌شده‌ی `GET /v1/home` می‌آید
(شمارش نوع ملک، محله‌های پرآگهی با میانگین قیمت و عکس، تازه‌های تأییدشده). اگر API در دسترس نباشد،
صفحه با بخش‌های خالی بالا می‌آید و خراب نمی‌شود.

- **عکس‌ها:** هیرو و عکس‌های نمونه‌ی آگهی‌ها عکس واقعی دبی‌اند (CC0 / Public Domain از Wikimedia Commons)؛ نام عکاس، مجوز و لینک هر فایل در `packages/db/assets/photos/CREDITS.json` است. نسخه‌های AVIF/WebP هیرو در `apps/web/public/hero/` از قبل ساخته شده‌اند (۷۰ کیلوبایت برای ۱۹۲۰ پیکسل) و با preload بالا می‌آیند. برای عوض کردن عکس هیرو، نسخه‌های `hero-{960,1440,1920,2560}.{avif,webp}` و `hero-fallback.jpg` را جایگزین کنید.
- **عکس‌های نمونه‌ی آگهی‌ها** بر اساس محله انتخاب می‌شوند (کارت مارینا عکس مارینا دارد)؛ `pnpm --filter @ashian/db seed -- --force` آن‌ها را دوباره می‌سازد. عکس داخلی آپارتمان‌ها در منابع آزاد کیفیت قابل‌قبول نداشت؛ آگهی‌های واقعی عکس خود مشاور را دارند.
- **عکس‌های آگهی و محله:** AVIF/WebP چند عرضه‌ی ساخته‌شده توسط worker با `<picture>`؛ جای‌نگهدار blurhash در سرور به یک PNG
  ۱۲×۹ تبدیل می‌شود. فقط عکس هیرو eager است.
- **کارایی:** JavaScript اولیه ≈ ۱۴۵ کیلوبایت gzip (حدود ۱۲۸ کیلوبایت آن React و Next است). برای حفظ این عدد، ریشه‌ی سایت
  `RootProvider` سبک دارد (بدون Tooltip، Toast و motion) و کامپوننت‌های کلاینت صفحه‌های عمومی از `cn`/Radix استفاده نمی‌کنند:
  آیکون‌ها در سرور رندر و به‌صورت prop داده می‌شوند و کلاس دکمه از `buttonClasses` می‌آید. صفحه‌ای که Tooltip/Toast/motion می‌خواهد
  `UIProvider` کامل را دور محتوایش می‌گذارد (مثل `/design`).

## صفحه‌ی نتایج و نقشه

مسیر `/search` و لندینگ‌های سئو `/{rent|sale}/{نوع?}/{N-bedroom|studio?}/{محله?}/{برج?}`
(مثل `/rent/apartment/2-bedroom/dubai-marina`، با تیتر و متن یکتا و لینک‌های داخلی؛ ترکیب نامعتبر ۴۰۴ می‌دهد).

- **همه‌ی وضعیت در URL است:** فیلترها، مرتب‌سازی، `page`، `bbox` و `view` (`list` / `split` / `map`). back مرورگر کار می‌کند، چیپ‌های فیلتر فعال و صفحه‌بندی لینک واقعی‌اند (بدون JavaScript هم کار می‌کنند). پارامتر خراب حذف می‌شود، صفحه نمی‌شکند.
- **نوار فیلتر چسبان:** معامله، نوع ملک، اتاق، قیمت (هیستوگرام لگاریتمی + اسلایدر دوسر) و «فیلترها» با شمارنده. پنل بیشتر در موبایل Bottom Sheet و در دسکتاپ پنل کناری است (`<dialog>` بومی) و تعداد نتایج پیش‌نویس را قبل از اعمال نشان می‌دهد.
- **کارت:** گالری سوایپی با شمارنده (۴ عکس اول)، برچسب‌ها، قلب، قیمت درشت، اتاق/حمام/متراژ، آدرس، تاریخ، مشاور با نشان و دکمه‌های تماس/واتساپ/پیام (فعلاً به بخش تماس صفحه‌ی آگهی می‌روند، چون شماره‌ها در API پنهان‌اند).
- **نقشه (MapLibre، بارگذاری تنبل):** پین قیمت‌دار، خوشه، هاور دوطرفه با کارت‌ها، «جستجو در این محدوده». سرویس کاشی با `NEXT_PUBLIC_MAP_STYLE_URL` عوض می‌شود؛ اگر در دسترس نباشد، پین‌ها روی پس‌زمینه‌ی ساده نمایش داده می‌شوند.
- **API تازه:** `GET /v1/amenities`، `GET/POST/DELETE /v1/saved-searches` (ذخیره‌ی جستجو؛ job هشدار در مرحله‌ی ۱۱)، و در پاسخ جستجو `photos`، `media` و `facets.priceHistogram`.
- **JS اولیه** صفحه‌ی نتایج ≈ ۱۴۷ کیلوبایت gzip؛ فیلترها بدون Radix ساخته شده‌اند و نقشه جدا بارگذاری می‌شود.

## تست سرتاسری

با اجرای `pnpm dev` در یک ترمینال، در ترمینال دیگر:

```bash
pnpm --filter @ashian/api smoke
```

۱۰۴ بررسی روی ورود، ساخت آگهی، آپلود عکس تا پردازش در worker، دسترسی‌ها، جستجو (فیلتر، ویژه، sync)، امنیت و کارایی.
(بین دو اجرای پشت‌سرهم حدود یک دقیقه صبر کنید؛ درخواست OTP محدودیت نرخ دارد.)

## ساختار پروژه

```
apps/
  web/        سایت (Next.js، App Router)
  api/        API (NestJS + Fastify)
  worker/     پردازش پس‌زمینه (BullMQ)
packages/
  shared/     تایپ‌ها، اسکیمای env، یکسان‌سازی متن فارسی، قیمت/تاریخ/متراژ، تنظیمات بازار
  db/         اتصال دیتابیس (Drizzle) و سرور lite
  infra/      آداپتورهای کش، صف و فایل
  search/     موتور جستجو: آداپتور Typesense و درون‌حافظه، facet، چینش منصفانه، همگام‌سازی
  config/     تنظیمات مشترک TypeScript و ESLint
  ui/         سیستم دیزاین (مرحله ۲)
```

## دستورهای رایج

```bash
pnpm dev            # اجرای همه‌چیز
pnpm build          # ساخت همه‌ی پکیج‌ها
pnpm test           # تست‌ها
pnpm lint           # ESLint
pnpm typecheck      # بررسی تایپ‌ها
pnpm format         # Prettier
```

برای یک پکیج: `pnpm --filter @ashian/shared test`

## تغییر بازار

همه‌ی تنظیمات بازار (ارز، واحد متراژ، تقویم، پیش‌شماره‌ها، مرکز نقشه) در
`packages/shared/src/market.ts` است. برای بازار دیگر فقط همین فایل را عوض کنید.

## امنیت

- فایل `.env` هرگز commit نمی‌شود.
- قبل از انتشار، همه‌ی `change-me-*` در `.env` را با مقدار تصادفی بلند عوض کنید.
- لاگ‌ها هدر درخواست (کوکی و توکن) را ذخیره نمی‌کنند.
